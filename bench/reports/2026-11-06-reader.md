# Reader benchmark, 2026-11-06

Can an Opus coordinator hand the reading of a project's memory folder (`.pm/`: verbatim dumps, the list of ideas, a status note) to a cheaper subagent? Internal run, **not publishable**: one fictional project, English, 5 seeds, and the fixture, the prompts and the harness were written by the same team. How the benchmark works is in [bench/README.md, "Reader benchmark"](../README.md).

**Setup:**
- Branch `feat/bench-reader` (`58c90be`), Claude Code 2.1.318, `claude -p` in the clean API environment of the README; costs are what each envelope reported, per model.
- Spec version 2 (sha256 `45b7a059…`), size `m` (~50k tokens of `.pm/`), seeds 1–5: each seed omits 3 live ideas from `items.md` (15 per configuration), at least one said in passing.
- Configurations: `opus` (Opus 5.5 reads itself), `opus+sonnet` and `opus+haiku` (Opus delegates the reading to a `pm-reader` subagent on Sonnet 5.5 or Haiku 5.5 and returns its answer). Main sessions at Claude Code's default effort (`medium`, seen in the transcripts).
- Prompts: v1 (the original, registered before the pilot) and v2 (a broad definition of "idea" plus a procedure that lists every idea before comparing; generic, with no wording from the fixture).
- **24.57 USD** for this batch (95 calls). Before it, the pilot (1 seed, spec v1, prompt v1, sizes s/m/l: 3.31 USD) and two single-call smokes (0.15 USD).

## What the results show

- **The prompt, not the model, was the problem.** With v1, every missed idea, in the three configurations, was one stated as a fact or a rule instead of a request: `cake-notice` (2 misses, Haiku), `prices-tax` and `monday-closed` (Haiku), `open-orders-limit` (Sonnet), `slot-reminder` (Sonnet and Opus). None of the request-shaped ideas was missed. With v2, nobody missed anything: in the `ideas` diagnostic every omitted idea was listed and marked missing (15 of 15 in every variant).
- **This confirms what the pilot's transcripts suggested:** the readers had the sentence in front of them and did not count it as an idea. The cheap readers searched for request phrasing ("I want", "should"); a broad definition and an explicit list fixed it.
- **Effort did not matter here.** v2 at the default effort already reaches 100 %, so `high` and `max` have nothing to add. `max` costs 2.9× and takes 4× longer (506 s per seed against 126 s) for Haiku.
- **Cost, per call at `m`, prompt v2:** the audit costs 0.57 USD with Opus alone, 0.37 with Opus + Sonnet and 0.13 with Opus + Haiku; a value lookup, 0.45, 0.23 and 0.06. Opus's share of a delegated call is about 0.05 USD: launching the subagent and returning its JSON.
- **The value task does not discriminate.** Even with values that change twice, changes stated relatively ("one hour earlier", "twice as many") and close distractors, every configuration scored 100 % with both prompts.
- **The hand-off is faithful.** In all 40 delegated audit calls, the `missing` list Opus returned is exactly a subagent's answer (in one call, `opus+haiku` v1 seed 5, it launched the reader three times and returned one of the answers), and Opus never read the dumps itself.

## Limits

- **Ceiling.** With v2, every configuration scores 100 % on this fixture, so it shows that Haiku is enough here, not where it stops being enough. A harder fixture (Spanish, longer dumps, ideas spread over two sentences, implicit changes) and more seeds are needed for that.
- **v2 was written after the pilot.** It is generic (the tests check it carries no fixture wording), and the three fact-phrased ideas it was tested on were added at the same time as v2. Its "do not skip a sentence because it states a fact" line comes from the failure the pilot showed.
- One fictional project, in English, 5 seeds; 15 omitted ideas per variant.
- It measures readers that start fresh. It does not measure the cost of an Opus coordinator that keeps what it read in its context for the rest of the session; that is stage 2 (an end-to-end scenario).
- At size `l` the first dump goes over the Read tool's 256 KB limit, so the readers fell back to Grep for that file. Real `.pm/` dumps should be split so each file can be read whole.
